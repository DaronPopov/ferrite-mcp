WHAT IS CREAM?
==============

cream is a background service that runs on your PC and gives Claude Code
(the AI assistant in your terminal) direct access to your machine — your
hardware, your files, your GPU, your build tools, everything — without
having to ask you for permission every time it needs to do something.

Think of it as the bridge between Claude's brain and your actual computer.


THE PROBLEM IT SOLVES
---------------------

When you use Claude Code out of the box, Claude can read and write files
and run commands, but it has to ask you to approve almost everything. It
also has no idea what your machine actually looks like — it doesn't know
what GPU you have, what CUDA version is installed, what libraries are
available, or what's currently running. So it guesses. It produces generic
code that might not match your setup, and every small verification requires
a back-and-forth with you.

cream fixes this by giving Claude a set of 89 pre-authorized tools it can
call silently in the background to get real answers from your machine before
it writes a single line of code.


HOW IT WORKS
------------

cream runs as an MCP server — MCP stands for Model Context Protocol, which
is Anthropic's standard for giving AI models access to external tools. When
you open Claude Code and cream is registered, Claude gains access to 89
tools it can call at any time without prompting you.

These tools cover everything a developer needs:

  - Ask the machine what GPU it has and what it's capable of
  - Find exactly where a library is installed and what flags to use
  - Run shell commands and get back clean structured results
  - Compile code and get errors back as {file, line, column} data
  - Search code with regex and get matches with context
  - Read git state, diffs, and commit history
  - Launch long-running processes in the background and watch their output
  - Run a chain of tasks as a pipeline (build → test → deploy)
  - SSH into remote machines and trigger builds there
  - Program FPGAs, run Vivado synthesis, parse timing reports
  - Profile GPU kernels, run GDB, inspect PyTorch checkpoints
  - Send notifications to your desktop or phone

All of this happens automatically as Claude works. You don't see it unless
something goes wrong. Claude just has better information and produces better
results.


THE BOOT SYSTEM
---------------

cream also ships a boot-time launcher called cream-autostart. This is a
Python script that runs automatically when your PC starts up. Here's what
it does every time you boot:

  1. Starts Claude Code inside a hidden terminal session (tmux)
  2. Waits for Claude to finish loading
  3. Enables Claude's "remote control" feature, which generates a URL
  4. Captures that URL
  5. Emails it to your Gmail address
  6. Optionally sends a push notification to your phone via ntfy.sh
  7. Keeps watching — if Claude crashes or closes, it automatically
     restarts it and sends you a fresh URL

The result: every time your PC boots, within about 60 seconds you get an
email with a link. You tap the link on your phone and you're talking to
Claude Code running on your PC, from anywhere. No SSH setup required,
no port forwarding, no VPN. Just a URL.

Each boot generates a completely fresh Claude session — not a resume of
the previous one — so you always start clean.


THE SESSION RESTART TOOL
------------------------

One of the 89 tools Claude has access to is called session_restart. When
Claude calls this tool, it kills its own terminal session. The watchdog
running in the background notices within 30 seconds, starts a new Claude
session, and sends you a fresh email with a new link.

This lets Claude hand off to a clean session on request — useful when a
conversation has gotten too long, when you want a fresh start, or when
you're done with one task and moving to another.


THE STRUCTURE
-------------

cream is built in Rust and organized as a workspace of 8 smaller packages:

  shell-core      The foundation — shared types, no system calls
  shell-lexer     Breaks shell input into tokens
  shell-parser    Turns tokens into a syntax tree
  shell-runtime   Actually runs shell commands, handles job control
  shell-hooks     The seam where AI integration plugs in
  shell-tui       The interactive terminal UI (prompt, history, completion)
  shell-mcp       The MCP server with all 89 tools
  shell-bin       The entry point that ties it all together

You interact with it in three ways:

  cream --mcp       Starts the MCP server (used by Claude Code automatically)
  cream             Opens an interactive shell
  cream -c "cmd"    Runs one command and exits


IN PLAIN TERMS
--------------

Your PC is sitting there with a powerful GPU, a specific CUDA version,
specific library paths, a git repo in a specific state, processes running
on specific ports. Before cream, Claude had to guess at all of this or ask
you repeatedly. With cream, Claude looks it up directly — the same way you
would open a terminal and check.

The result is that Claude writes code that actually fits your machine,
finds bugs faster because build errors come back as structured data instead
of raw text, and can handle long-running tasks (like an hour-long FPGA
synthesis job) by watching them in the background and reporting back when
done.

And because of the boot system, Claude is always running and always
reachable — even when you're away from your desk.
